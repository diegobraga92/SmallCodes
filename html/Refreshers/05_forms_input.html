1. Form Element

Attribute Values Description
action URL Where to send the form data
method GET, POST HTTP method for submission
enctype application/x-www-form-urlencoded (default), multipart/form-data (files), text/plain How to encode the data
novalidate Boolean Disable HTML5 validation
autocomplete on, off Enable/disable autofill
target _self, _blank, _parent, _top Where to display the response
GET vs POST:
  • GET: Data in URL (visible, bookmarkable, cached). Use for searches, filters.
  • POST: Data in request body (not cached, no size limit). Use for mutations, logins, file uploads.

5. HTML5 Form Validation

CSS Pseudo-classes for Validation

/* Style valid/invalid fields */
input:valid { border-color: #28a745; }
input:invalid { border-color: #dc3545; }

/* Style required fields */
input:required { border-left: 3px solid #e44d26; }
input:optional { border-left: 3px solid #ccc; }

/* Style placeholder */
input::placeholder { color: #999; font-style: italic; }

/* Style when user has interacted (dirty state) */
input:focus:invalid { box-shadow: 0 0 3px rgba(220,53,69,0.5); }

6. Custom Validation with JavaScript
Validation strategy:
  • Use HTML5 validation for simple rules (required, type, pattern)
  • Use JavaScript for complex rules (password match, API checks)
  • Always validate on the server too — client validation is convenience, not security
  • Show errors inline near the field, not in alerts
  • Validate on blur (when leaving a field) and on submit

Accessibility checklist:
  • Every input must have a label (visible or screen-reader-only)
  • Use aria-describedby to associate hints and errors
  • Use role="alert" on error messages
  • Use aria-live="polite" for status updates
  • Don't remove focus outlines on form fields
  • Ensure tab order follows visual order
  • Test forms with keyboard-only navigation

8. Form Security and Best Practices

Security Measures

Best Practices Checklist

  • Use appropriate input types — email, tel, number, etc.
  • Set maxlength on all text inputs
  • Use placeholder text as examples, not as labels
  • Disable the submit button after submission to prevent double-submit
  • Show clear error messages near the relevant field
  • Preserve form values on validation failure (don't clear the form)
  • Use autocomplete attributes for better UX (name, email, address)
  • Always validate server-side — client validation is for UX, not security
  • Use HTTPS — forms send data over the network
  • Add a honeypot field to catch spam bots
