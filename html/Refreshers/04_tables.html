Spanning gotchas: When using colspan or rowspan, the total number of cells in each row must be consistent. A cell that spans 2 columns counts as 2 cells. Missing cells can cause layout issues.

Don't use tables for layout! In the past, tables were used for page layout. This is outdated and harmful for accessibility. Use CSS Grid or Flexbox for layout. Tables are for tabular data only.

Technique 2: Stacked on Mobile (CSS)

/* Convert table to card layout on small screens */
@media (max-width: 600px) {
    table, thead, tbody, tfoot, tr, th, td {
        display: block;
    }

    /* Hide headers visually but keep for screen readers */
    thead tr {
        position: absolute;
        top: -9999px;
        left: -9999px;
    }

    /* Add data-label attribute to td for pseudo-element labels */
    td {
        position: relative;
        padding-left: 50%;
    }

    td::before {
        content: attr(data-label);
        position: absolute;
        left: 10px;
        font-weight: bold;
    }
}

8. Table Styling Best Practices

/* 1. Collapse borders for clean look */
table { border-collapse: collapse; }

/* 2. Add zebra striping for readability */
tbody tr:nth-child(even) { background: #f9f9f9; }

/* 3. Hover effect for interactivity */
tbody tr:hover { background: #f0f0f0; }

/* 4. Consistent padding */
th, td { padding: 8px 12px; }

/* 5. Align numbers to the right */
td.numeric { text-align: right; font-variant-numeric: tabular-nums; }

/* 6. Sticky header for long tables */
thead th { position: sticky; top: 0; z-index: 1; }

/* 7. Responsive font size */
@media (max-width: 600px) {
    th, td { font-size: 0.875rem; padding: 6px 8px; }
}
Table checklist:
  • Use for table description
  • Use , ,
  • Add scope to all elements
  • Use headers + id for complex tables
  • Make tables responsive (scroll or stack on mobile)
  • Use zebra striping for readability
  • Align numbers to the right
  • Never use tables for layout
