========================================================
🚀 Senior C++ 30-Minute Interview Challenges
========================================================

Goal: Train for senior-level interviews — not syntax drills.

These exercises force:
- API design decisions
- RAII correctness
- Value vs reference semantics
- Concurrency correctness
- Exception safety
- STL fluency
- Tradeoff discussion
- Clean abstractions

Each is scoped for ~30 minutes but rich in senior signal.


========================================================
🔥 HOW TO PRACTICE (IMPORTANT)
========================================================

For each 30-minute session:

1. Spend 5 minutes designing API first
2. Write clean, modern C++ (C++17+ minimum)
3. Add minimal unit tests (or test main)
4. Explain tradeoffs aloud:
   - Why this container?
   - Why this synchronization?
   - Exception safety level?
   - Strong/Basic/No-throw guarantee?
5. Explain how you'd productionize it.

That last step is what separates senior from mid-level.


========================================================
CORE SYSTEM DESIGN IN MINIATURE
========================================================

1. In-Memory Key-Value Store
--------------------------------------------------------
Design:

class KvStore {
public:
    void set(std::string key, std::string value);
    std::optional<std::string> get(std::string_view key) const;
    bool erase(std::string_view key);
};

Senior signal:
- std::string vs std::string_view
- const correctness
- API clarity
- Complexity discussion

Extension: Add TTL support.


2. Thread-Safe Counter
--------------------------------------------------------
Implement:

class Counter {
public:
    void increment();
    size_t value() const;
};

Spawn multiple threads incrementing it.

Senior signal:
- std::mutex vs std::atomic<size_t>
- False sharing discussion
- Memory ordering basics


3. LRU Cache
--------------------------------------------------------
Fixed capacity cache with:

- get(key)
- put(key, value)

Senior signal:
- std::unordered_map + std::list
- Iterator stability
- O(1) guarantees
- Move semantics discussion


4. Token Bucket Rate Limiter
--------------------------------------------------------
Implement allow() that respects rate limits.

Senior signal:
- std::chrono
- Time measurement precision
- Thread safety considerations


5. Thread Pool
--------------------------------------------------------
