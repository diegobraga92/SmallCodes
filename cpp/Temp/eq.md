# 5-Day JD1 Preparation Plan (Fully Aligned)

| Day | What to Do | How This Maps to JD |
|-----|------------|---------------------|
| **Day 1** | **C++ Internals + Templates + DSA Awareness**<br><br>- Deep dive: RAII, move semantics, object lifetime<br>- Implement a simplified `unique_ptr`<br>- Learn templates: function/class templates, specialization basics<br>- Compare templates vs virtual (performance tradeoffs)<br>- **DSA overlay:** analyze complexity of operations (copy vs move, allocations)<br>- **System thinking:** when do abstractions add hidden cost?<br>- **Testing:** validate ownership correctness, avoid leaks/double free<br>- **Real-world:** identify where UB could crash production systems | **“Strong C++ understanding”** → ownership, lifetime<br>**“Template code”** → explicit JD requirement<br>**“Data structures & algorithms”** → complexity + behavior<br>**“Recognize system limits”** → abstraction cost awareness<br>**Production system** → avoiding UB in real systems |
| **Day 2** | **Memory, Cache & Data Layout + Performance Reasoning**<br><br>- Study cache hierarchy, cache lines<br>- Analyze struct padding & alignment<br>- Compare `vector` vs `list` (DSA tradeoffs + cache impact)<br>- Transform AoS → SoA<br>- Reduce allocations (reserve, pooling)<br>- **DSA overlay:** container choice & complexity vs memory layout<br>- **System thinking:** identify memory bottlenecks<br>- **Testing:** micro-benchmark or reason about performance changes<br>- **Real-world:** think in p99 latency, not averages | **“Low/ultra-low latency”** → cache & layout are critical<br>**“Data structures & algorithms”** → container tradeoffs<br>**“Recognize system limits”** → memory/cache bottlenecks<br>**Performance systems** → latency spikes from allocations |
| **Day 3** | **Concurrency & Thread Safety + Correctness**<br><br>- Study threads, mutexes, race conditions<br>- Learn `std::atomic` (core ops + intuition)<br>- Understand memory ordering (high-level)<br>- Implement thread-safe queue (mutex-based)<br>- Debug broken concurrent code<br>- **DSA overlay:** queue design tradeoffs (throughput vs contention)<br>- **System thinking:** where are contention bottlenecks?<br>- **Testing:** simulate race conditions, validate correctness<br>- **Real-world:** what happens under load or high contention? | **“Thread-safety code”** → explicit JD requirement<br>**“Async code (foundation)”** → concurrency base<br>**“Recognize system limits”** → contention & race conditions<br>**Production systems** → correctness under concurrency |
| **Day 4** | **Async Systems + Lock-Free + System Design**<br><br>- Learn task-based concurrency, thread pools<br>- Implement simple thread pool<br>- Study CAS, lock-free basics<br>- Compare blocking vs busy-wait<br>- Design low-latency task system<br>- **DSA overlay:** queue/task scheduling strategies<br>- **System thinking:** latency vs CPU tradeoffs (spin vs sleep)<br>- **Testing:** ensure no deadlocks, validate task execution correctness<br>- **Real-world:** minimize latency spikes, handle burst workloads | **“Asynchronous code”** → explicit JD requirement<br>**“LockFree thinking”** → strong nice-to-have signal<br>**“Recognize system limits”** → CPU vs latency tradeoffs<br>**Low latency systems** → avoiding blocking & contention |
| **Day 5** | **Networking + Linux + Integration + Validation**<br><br>- Study TCP basics, buffering, blocking vs non-blocking I/O<br>- Learn epoll/select (conceptual)<br>- Study processes vs threads, syscall cost<br>- Mock interview:<br>&nbsp;&nbsp;• optimize slow code<br>&nbsp;&nbsp;• design thread-safe system<br>&nbsp;&nbsp;• review buggy code<br>- **DSA overlay:** buffering strategies, queueing<br>- **System thinking:** I/O bottlenecks, backpressure<br>- **Testing:** failure scenarios (timeouts, partial reads)<br>- **Real-world:** latency under network load, system stability | **“Networking”** → explicit JD requirement<br>**“Linux internals”** → explicit nice-to-have<br>**“Recognize system limits”** → I/O & syscall overhead<br>**Production systems** → handling failures & load |
