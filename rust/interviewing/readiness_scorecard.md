# Readiness Scorecard

Source: *Senior Engineer Interview Preparation* (Topics 3, 4, and 7), §7.

Check an item **only when you can demonstrate it without relying on notes**. Use the
checklist to identify where another focused practice session will make the biggest
difference; the total is not an absolute measure of ability.

## Coding
- [ ] Solve a medium problem in 35–45 minutes.
- [ ] Explain complexity and test edge cases.
- [ ] Implement and debug unfamiliar code while speaking.

## Technical depth
- [ ] Explain ownership, lifetimes, RAII, and move semantics.
- [ ] Reason about races, deadlocks, and memory ordering.
- [ ] Diagnose a production latency or reliability issue.

## System design
- [ ] Lead a 45-minute design discussion.
- [ ] Explain scaling, failure recovery, and backpressure.
- [ ] Discuss data consistency, security, and observability.

## Experience and communication
- [ ] Deliver a clear 90-second introduction.
- [ ] Deep-dive into three resume projects.
- [ ] Answer behavioral questions with concrete outcomes.

## Job search
- [ ] Identify suitable remote international roles.
- [ ] Explain the contracting period and preferred next role.
- [ ] Complete at least one full mock interview loop.

---

## Suggested interpretation

| Status | What to do next |
|--------|-----------------|
| Not yet reliable | Practice the skill with notes, then repeat without notes under a time limit. |
| Mostly reliable | Repeat in a mock setting and work on clarity, speed, and edge cases. |
| Interview-ready | Keep it sharp with brief spaced practice; prioritize remaining weak areas. |

---

> **Final reminder:** Don't build a large portfolio project solely for interview
> preparation. Your existing work is rich material. Spend the time reconstructing
> technical details, practicing coding, and rehearsing explanations. Start selected
> applications before **Day 30** rather than waiting to feel perfectly ready.
